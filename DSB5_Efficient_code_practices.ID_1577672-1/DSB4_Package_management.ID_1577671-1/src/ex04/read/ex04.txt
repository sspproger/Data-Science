Профилирование — это процесс измерения производительности программы: сколько времени тратится на выполнение разных функций, сколько памяти используется, как часто вызываются те или иные части кода.

cProfile — встроенный в Python профилировщик, который измеряет время выполнения каждой функции.
cProfile — это инструмент, который помогает понять "где программа тратит время", чтобы оптимизировать именно эти участки кода.

pstats — библиотека для анализа и сортировки результатов cProfile.

total time (tottime) 		#время, проведённое в функции без учёта вызовов других функций.
percall (tottime/ncalls)   	#Среднее время одного вызова
cumulative time (cumtime)	#время с учётом вложенных вызовов.
ncalls				#количество вызовов функции.

Замена requests на httpx может ускорить работу, если httpx использует HTTP/2 или более эффективные соединения (но это зависит от многих факторов, включая сеть и сервер).

Почему это важно для тебя в этом задании?
1.Найти time.sleep(5) — в первом профиле ты увидишь, что time.sleep занимает почти всё время.
2.Сравнить библиотеки — увидишь, что httpx работает быстрее/медленнее requests.
3.Найти узкие места — возможно, парсинг HTML медленнее, чем загрузка страницы.


"Как видно из цифр, количество вызовов функций не всегда коррелирует со временем выполнения. В моём случае:

Оригинальный скрипт (ncalls.txt) делает 1 007 274 вызова за 2.759 сек

Улучшенный с другим HTTP-клиентом (http.txt) делает 997 365 вызовов за 3.462 сек

Несмотря на меньшее количество вызовов, улучшенная версия работает медленнее. Это показывает, что:

Новый HTTP-клиент делает меньше, но более тяжёлых вызовов

Основное время всё равно тратится на сетевые операции (read из сокета)

Для реальной оптимизации нужно смотреть не на количество вызовов, а на их тип и длительность

В моём случае лучшая оптимизация была достигнута не сменой HTTP-клиента, а:

Удалением time.sleep(5) (самый большой выигрыш)

Использованием сессий requests.Session() для reuse соединений

Параллелизацией запросов (если применимо)"

Больше всего времени (3.492 сек) тратится на HTTP-запрос через библиотеку httpx (функции get и request).
Основное время выполнения программы связано с сетевым I/O, а не с вычислениями в коде.
Время выполнения модуля financial_enhanced.py почти полностью определяется вызовом httpx.get.
Рекурсивные вызовы отмечены форматом 332/1 (332 вызова, из которых 1 примитивный).

Проще говоря:
Примитивный вызов = вызов из другого места в коде (не из этой же функции)

Непосредственный вызов = рекурсивные вызовы самой себя

В вашем случае функция builtins.exec была вызвана 1 раз извне, но в процессе выполнения она вызвала саму себя 331 раз рекурсивно.
Итого: 1 + 331 = 332 вызова, но примитивный — только 1.

2348 — количество строк в полном отчёте (каждая строка = информация об одной функции)

5 — количество строк, показанных вам после фильтрации (топ-5 по cumulative time)
